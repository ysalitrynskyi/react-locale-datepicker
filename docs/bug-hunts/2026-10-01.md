# Pre-release review 2026-10-01 — findings and resolutions

An independent review of the prepared 0.6.0 against 0.5.1, made before it
was published, with one question: does upgrading break anything for an
existing consumer? It compared the two versions in Chromium and jsdom, read
the main consumer's use of the picker, and reported five regressions and two
gaps in the changelog. Each was reproduced again here before it was fixed.
Regression tests name their id (`RV-0`), in
`tests/prerelease-review.test.tsx`, `e2e/bughunt.spec.ts` and
`e2e/bughunt-styles.spec.ts`.

All five regressions came from 0.6.0's own fixes, which is the case for
reviewing a release as a whole after reviewing its parts.

The same reviewer then went over the fixes: re-ran each reproduction against
them, deleted each fix in turn to see which test went red, and checked the
claims the fixes made. That second pass added RV-07 to RV-09.

| ID | Verdict | Commit | Note |
| --- | --- | --- | --- |
| RV-01 | Fixed | `abb72a4` | A portaled calendar that did not fit beside the field was shifted back into the viewport, over the field (BH-052's fix). It now keeps to its side and its height is capped, so it scrolls inside. |
| RV-02 | Fixed | `82055ed` | The focus ring on a filled cell was drawn in the fill's foreground colour (BH-022's fix), invisible when a CSS reset strips the fill. The ring keeps the ring colour; a band inside it supplies the contrast against the fill. |
| RV-03 | Fixed | `aea68be` | Closing the calendar under a focused control fires no blur, so leaving from inside the calendar (BH-014's model) never reached `onBlur`. A press outside, or a finger pick, while focus is inside the calendar now reports leaving the widget, once. |
| RV-04 | Fixed | `f2b66e0` | The first-letter casing (BH-036's fix) used the upper-case mapping, which turns Georgian into Mtavruli. It now uses the title-case form; Georgian is left as written. |
| RV-05 | Fixed | `aea68be` | The date an outside press committed was kept for the next `onBlur` even after a later commit, which then received the older date. The latest commit is recorded, and the record is cleared when the value changes. |
| RV-06 | Fixed (docs) | `1dc5ea0` | Behaviour changes listed only under *Fixed*, or nowhere: the focus ring on an errored or disabled field, canonical tags from `resolveLocale`, `"missing"` with a committed value, outside-press commits, the first-enabled-month opening, and the portaled placement. All are under *Changed* in the changelog. |
| RV-07 | Fixed | `9c1a4c9` | RV-01's height cap had no lower bound. With the side frozen, scrolling the field to the viewport edge shrank the calendar to an empty strip of padding and border, and above the field that strip overlapped it. The cap stops at 120px; closer to the edge the calendar runs past it, still clear of the field. |
| RV-08 | Fixed (tests) | `69828f7` | Three parts of RV-03 and RV-05 could be deleted with the suite still green: the reset that lets a second exit be reported, recording a typed commit for a parent that has not rendered it yet, and dropping that record when the value changes. Each has a test now, seen to fail without its code. |
| RV-09 | Corrected (docs) | `82cf5e2` | RV-03's notes said Android focuses a tapped day. In Chromium's Android emulation a tap leaves focus where it was, because the popover cancels mousedown. The case the code handles is a finger pick while focus is already inside the calendar, and the comment, changelog, API reference and D21 say that now. |

## Not verified here

- RV-01 was reproduced by resizing a Chromium viewport, not with a phone
  keyboard that resizes the page.
- RV-04 was reproduced in Node's ICU; the Playwright Chromium build has no
  Georgian data.
- RV-09 rests on Chromium's Android emulation, not on a phone.
- Firefox and WebKit were not run locally (CI runs them).
- The consumer's own suite was not run against 0.6.0.
