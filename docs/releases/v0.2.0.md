# react-locale-datepicker 0.2.0

**Status: prepared, not published.** Publishing needs explicit operator
approval for this specific release (`AGENTS.md`, `docs/RELEASING.md`).

Theming and accessibility. Everything is additive except four accessibility
corrections that change defaults on purpose, plus three real bugs fixed.

## Highlights

**A published styling contract.** Every element the component renders now
carries a `data-part` attribute, driven by a single exported `ANATOMY` list
that also types the `classNames` and `styles` maps and generates
[the anatomy document](../ANATOMY.md). Styling the picker without importing
its stylesheet is now a documented, tested contract rather than a set of
class names you were never promised.

**Four named themes** — `default`, `minimal`, `soft`, `high-contrast` —
selectable from CSS (`data-rldp-theme`) or from React (`themeName`). They
nest, and the nearest one wins.

**Localized digits actually work.** Typed-digit normalization covered exactly
two Arabic-Indic ranges before. Users whose locale defaults to Bengali,
Devanagari, Myanmar or Thai digits could not type a date **at all** — their
digits matched no range and were then stripped as non-digits. The digit map
is now generated from `Intl.NumberFormat`, so every numbering system the
engine knows works, with no table to maintain.

**Ancestor token overrides work.** `README.md` has documented setting
`--rldp-*` on an ancestor since 0.1.0 and it never worked: the stylesheet
declared every token on the picker root, and an element's own declaration
beats an inherited value regardless of cascade layer.

## Accessibility corrections (default changes)

- The day grid uses **`role="grid"`** semantics with `aria-selected` on the
  gridcell. `aria-current="date"` moves from the selection to **today**.
- Weekday cells are **`columnheader`s** announced with the long weekday name.
  They were `aria-hidden="true"`.
- The calendar trigger was **`aria-hidden="true"`**; it is now named and
  restates the committed date ("Change date, 17 November 2026"). It remains
  outside the tab order — the input is the tab stop.
- The month and year live region is **`aria-atomic`**, so a year-crossing
  navigation is no longer announced as a bare year. The APG one-time keyboard
  help is announced when focus first enters the grid.

No keyboard or focus behaviour changed. The roving-tabindex chain, the
input-stays-focused-on-open rule and focus-returns-on-close are all under
regression test.

## Upgrading

Nothing to do. No prop was removed or renamed, and `Slot` only grew.

If you assert on the day grid's DOM in your own tests, note the two new
wrapper levels (`role="rowgroup"` → `role="row"` → `role="gridcell"`) and
that the selected day is marked by `aria-selected` on its gridcell rather
than by `aria-current` on the button.

## Verification

- 112 unit tests, green under `TZ=UTC`, `America/Los_Angeles` and
  `Asia/Tokyo`.
- Playwright: 192 passed, 6 viewport-skipped, across Chromium, Firefox and
  WebKit at 320 / 768 / 1280.
- The oklch palette conversion was pixel-diffed against the 0.1.0 renders:
  zero solid-fill pixels changed.
- The demo in `examples/` was verified against the built package.

**Not verified:** the manual screen-reader matrix (VoiceOver, NVDA, JAWS,
TalkBack). The accessibility work above is covered by automated regressions
and an axe pass only. Running real screen readers needs a human.
