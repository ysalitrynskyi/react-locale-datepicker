Driven by operator testing of the 0.2.0 live demo: the typed-input path and
the open calendar lived in separate worlds, and "today" could not follow a
business timezone.

## Fixed

- Typing a complete date while the calendar is open navigates the grid to it
  live, clamped by `minDate`/`maxDate` like every other navigation path,
  with DOM focus staying in the input.
- Reopening the calendar honours an uncommitted typed draft instead of the
  stale committed value.
- Separator keystrokes are accepted instead of silently stripped: `.` `,`
  `/` `-` and the Arabic and ideographic commas close the current segment
  and pad a single-digit day or month, so `1.7.2026` masks to `01.07.2026`.
  Pure-digit typing masks exactly as before, under a regression guard.

## Added

- `timeZone` prop (decision D16): derive "today" — the ring, the default
  view month, the default keyboard target and the default year range — in a
  fixed IANA zone, for availability rules that run on a seller's calendar
  day. `"default"` and `"system"` mean the visitor's own zone; invalid
  names fall back to it. Committed values remain local-midnight `Date`s —
  this never converts the value.
- `today` prop: inject "today" outright; wins over `timeZone`.
- `todayInTimeZone(timeZone)` export, so `shouldDisableDate` can be built
  on the same business day the component's marker uses.
- The live demo gained a "Business timezone" example anchored to
  Pacific/Kiritimati (UTC+14), where the seller's today is most visitors'
  tomorrow.

Suites: 128 unit tests (3 timezones), 192 Playwright checks across
Chromium, Firefox and WebKit. No API removed or renamed; everything new is
opt-in with 0.2.0 behaviour as the default.
