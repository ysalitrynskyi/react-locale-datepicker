# 0.4.0

Adoption-contract release. Prompted by a live travel-insurance checkout that
audited 0.3.3 against its in-product date picker and found the package
already a superset — but needed the behaviours pinned, and one open
question about `overflow: hidden` resolved, before putting it on a payment
path.

## What shipped

- **`portal` prop** — opt-in portal escape for clipped cards (D17). Default
  unchanged.
- **Contract tests** — `ua`→`uk`, local midnight (incl. Kathmandu TZ), no
  storage, SSR, fixed `dd.MM.yyyy`.
- **Labels docs** — four English defaults called out as must-override;
  nav labels stay Intl-derived.
- CI timezone matrix extended with `Asia/Kathmandu`.

## Upgrade

No breaking changes. Existing 0.3.x call sites keep working.

If the picker sits inside an `overflow: hidden` card (rounded form shells
are the common case), add `portal` or `portal={hostEl}`:

```tsx
<LocaleDatePicker portal value={…} onChange={…} placeholder="dd.mm.yyyy" />
```

For non-English UIs, pass `labels` for the four English defaults
(`keyboardHelp`, `openCalendar`, `changeDate`, `closeCalendar`).
`previousMonth` / `nextMonth` do not need translating.

## Suites

- Unit: 168 tests, green under `TZ=UTC`, `America/Los_Angeles`,
  `Asia/Tokyo`, `Asia/Kathmandu`.
- Playwright: browser matrix plus overflow clip / portal escape specs.
